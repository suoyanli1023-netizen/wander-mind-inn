# 心绪漫游小栈产品演进记录

## 1. 产品背景与用户问题

情绪表达有门槛：低能量用户难以持续写长文本，带说教或诊断感的心理产品也容易增加压力。心绪漫游小栈让用户先选图像、空间、摆件或简短答案，以视觉互动降低表达负担，再以温柔的本地文字承接体验。现有心理联想是产品内容与前端规则，不是医疗诊断。

## 2. 当前业务流程

用户进入产品，在首页选择互动模块，完成对应任务，查看温柔承接和本地规则生成的心理联想；可将结果保存为情绪贴纸，再回到心绪旅程查看。浏览器本地保存旅程及部分模块进度。**当前尚未接入真实 AI**，也没有服务端心理分析。

## 3. 五个功能模块

| 模块 | 当前入口与体验 | 完成后的结果 |
|---|---|---|
| 极简小屋 | 选择房屋、背景、情绪、摆件和人物细节 | SVG 预览、安慰语、解读与小屋贴纸 |
| 氛围小屋 | 用图片素材搭建情绪空间 | 空间解读与氛围贴纸 |
| 图像联想（现有页面称“绘画投射”） | 选择抽象图像并回答三个问题 | 图像联想文字与贴纸 |
| 放走坏心情 | 写下烦恼，经历便签与漂流瓶流程 | 安慰与释放贴纸 |
| 此刻心意 | 完成十道二选一题 | 情绪需求结果与贴纸 |

## 6. 当前架构

真实前端架构是原生 `index.html`、11 个独立 CSS、11 个普通同步外部 JS，以及仍保留在主内联脚本中的氛围小屋、此刻心意和公共 UI。`js/house.js` 已独立，`js/atmosphere.js` 和 `js/choice.js` 尚不存在。

`soul_journey` 只保存 `archives`、`houseState`、`drawState`、`worryState`、`choiceState`。登录演示、音效、API 设置使用其他 localStorage key。GitHub/Google 只有授权跳转与演示回调；微信使用 postMessage；邮箱验证码由前端生成和显示。前端 API Key 输入仅为预留 UI。**AI Gateway、Safety Guard、Agent 和服务端数据库均未实现。**

## 7. AI 产品目标架构（规划中）

以下均是规划，不是已上线能力：

- **双层反馈**：先给短句承接，再在用户愿意展开时给解释与探索建议。
- **Safety Guard**：在生成内容前后识别高风险情境，限制诊断式表达并提供合适转介。
- **Journey Orchestrator 与 Reflection Cards**：把互动任务与旅程贴纸组织成可回顾的反思卡片。
- **结构化 JSON**：约束服务端输出字段、证据来源和展示层分离。
- **降级策略**：AI 服务不可用时仍能提供清楚标注的本地内容。
- **埋点与评估**：衡量完成率、低能量用户负担、反馈安全性和贴纸回访行为。

落地这些能力前，需要独立设计数据边界、服务端密钥管理、内容安全与评估方法。

## 8. 当前已知问题与边界

- `treehouse` / `igloo` 是 HTML 与 STATE 的基底值，部分安慰语和解读规则却使用 `tree` / `dome`；这是既有映射问题，04C-4 未修复。
- 氛围小屋能显示结果，但 `atmosphereState.done` 未被写为 `true`；当前及拆分前代码均无写入语句。
- 认证仍是演示流程，不具备生产级服务端身份验证。
- API Key 设置是前端预留 UI，不能视为真实 AI 接入。
- 没有真实 AI 请求、服务端 AI Gateway 或数据库。
