# 心绪漫游小栈产品演进记录

## 1. 产品背景与用户问题

情绪表达有门槛：低能量用户难以持续写长文本，带说教或诊断感的心理产品也容易增加压力。心绪漫游小栈让用户先选图像、空间、摆件或简短答案，以视觉互动降低表达负担，再以温柔的本地文字承接体验。现有心理联想是产品内容与前端规则，不是医疗诊断。

## 2. 当前业务流程

用户进入产品，在首页选择互动模块，完成对应任务，查看温柔承接和本地规则生成的心理联想；可将结果保存为情绪贴纸，再回到心绪旅程查看。浏览器本地保存旅程及部分模块进度。**当前尚未接入真实 AI**，也没有服务端心理分析。

## 3. 五个功能模块

| 模块 | 当前入口与体验 | 完成后的结果 |
|---|---|---|
| 极简小屋 | 选择房屋、背景、情绪、摆件和人物细节 | SVG 预览、安慰语、解读与小屋贴纸 |
| 氛围小屋 | 用图片素材搭建情绪空间 | 空间解读与氛围贴纸 |
| 图像联想（现有页面称“绘画投射”） | 选择抽象图像并回答三个问题 | 图像联想文字与贴纸 |
| 放走坏心情 | 写下烦恼，经历便签与漂流瓶流程 | 安慰与释放贴纸 |
| 此刻心意 | 完成十道二选一题 | 情绪需求结果与贴纸 |

## 4. TRAE 阶段落地

## 6. 当前架构与已经实现的产品能力

真实前端架构是原生 `index.html`、11 个独立 CSS、13 个普通同步外部 JS 和 2 个内联 script。journey、worry、draw、house、atmosphere、choice 均已拆分；主内联 script 只保留生命周期、状态恢复、吉祥物、设置、情绪标签和折叠等公共代码。

`soul_journey` 保存 `archives`、`houseState`、`atmosphereState`、`drawState`、`worryState`、`choiceState`。登录演示、音效、API 设置使用其他 localStorage key。GitHub/Google 只有授权跳转与演示回调；微信使用 postMessage；邮箱验证码由前端生成和显示。前端 API Key 输入仅为预留 UI。**AI Gateway、Safety Guard、Agent 和服务端数据库均未实现。**

当前已经实现并通过本地整合验收的产品能力包括：演示登录、旅程新建／重命名／删除、五个情绪互动模块、结果承接与本地规则解读、五类情绪贴纸、各核心模块进度与音效偏好的本地持久化、XSS 文本安全显示、移动与桌面响应式页面。05A 进一步完成基底映射、氛围状态一致性、生命周期治理和移动端默认放置；这里的“通过”指本地与测试环境验收，不表示已经生产上线。

## 7. AI 产品目标架构（规划中）

以下均是规划，不是已上线能力：

- **双层反馈**：先给短句承接，再在用户愿意展开时给解释与探索建议。
- **Safety Guard**：在生成内容前后识别高风险情境，限制诊断式表达并提供合适转介。
- **Journey Orchestrator 与 Reflection Cards**：把互动任务与旅程贴纸组织成可回顾的反思卡片。
- **结构化 JSON**：约束服务端输出字段、证据来源和展示层分离。
- **降级策略**：AI 服务不可用时仍能提供清楚标注的本地内容。
- **埋点与评估**：衡量完成率、低能量用户负担、反馈安全性和贴纸回访行为。

落地这些能力前，需要独立设计数据边界、服务端密钥管理、内容安全与评估方法。

## 8. 当前产品成熟度、已知边界与未实现能力

- 模块化治理、体验修复、状态一致性、生命周期治理和自动化质量门禁已经形成稳定前端基线；05A 最终验收 FAIL=0、BLOCKED=0。
- 认证仍是演示流程，不具备生产级服务端身份验证。
- API Key 设置是前端预留 UI，不能视为真实 AI 接入。
- 没有真实 AI 请求、Agent、Safety Guard、服务端 AI Gateway 或数据库。

## 9. 后续产品迭代建议

机械拆分阶段已经结束。以下均为建议，尚未开始，须分别设计、授权和验收：

### P0：真实 AI 接入前的安全、隐私和服务端架构

- 将 API 密钥移出浏览器，设计服务端 AI Gateway、认证、速率限制、审计和秘密管理。
- 明确情绪数据的收集边界、告知与同意、保留期限、删除机制和隐私政策。
- 建立 Safety Guard、危机场景转介、输出结构约束、降级策略和人工内容审核标准。
- 区分本地规则反馈与 AI 生成内容，避免把心理联想呈现为诊断。

### P1：状态、交互和可维护性

- 持续为已持久化场景建立 schema 演进策略、容量边界和异常数据观测。
- 补充键盘可访问性、触摸设备人工兼容矩阵和低性能设备动画评估。
- 将演示认证与生产认证在界面和代码边界上清楚分离。

### P2：指标、评估和增长实验

- 定义模块进入、开始、完成、贴纸保存、旅程回访等事件和最小化数据方案。
- 建立内容安全、任务完成率、低能量用户负担和反馈有用性的评估集。
- 在具备隐私与安全基础后，再设计新手引导、模块推荐、回访提醒和商业化假设实验。

不得从当前仓库推断用户规模、转化率、留存率或 AI 效果；项目目前没有这些真实数据。
